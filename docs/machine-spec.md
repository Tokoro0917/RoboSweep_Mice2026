## 1. 全体の構成

```
 [リモコン]                         [機体]
 XIAO ESP32C3                       ESP32（受信用）
 ボタン 8 個 + 液晶  --ESP-NOW-->    │ UART4 (115200bps)
                                    ▼
                                   STM32F446（DOM-SWEEP 基板）
                                    ├─ ステッピングモーター × 2（SLA7073 × 2）
                                    ├─ 赤外線の壁センサ × 4
                                    ├─ アーム用サーボ RS204MD × 2（USART1）
                                    └─ 吸引ファン（PWM）

 （予定）XIAO ESP32S3 Sense のカメラでボールを探し、UART で STM32 に送る
```

### マイコン

- STM32F446RETx
- クロックは内蔵の HSI（16MHz）と PLL で 180MHz
  - 基板には 10MHz のセラミック発振子（Y1）が載っているが、今は使っていない
- 書き込みとデバッグは J3（SWD）

| PB14 | MOTOR_CW/CCW_R | モーターの回転方向 |

### タイマー

| タイマー | 用途 | 設定 |
| --- | --- | --- |
| TIM3 | 片方のモーターのパルス | 90MHz / 8 = 11.25MHz。ARR でパルスの周期を変える |
| TIM8 | もう片方のモーターのパルス | 180MHz / 16 = 11.25MHz |
| TIM4 | 吸引ファンの PWM | 周期 100。比較値 2 で ON、100 で OFF |
| TIM6 | 制御の割り込み | **1kHz**（1ms ごと） |

## 4. 通信

### リモコン → 機体の ESP32（ESP-NOW）

リモコンは 50ms ごとに、8 個のボタンの状態（`bool` × 8 の構造体）を送ります。

### 自律機どうし（2 台のとき）

STM32 が自分の位置を ESP32 に送り、ESP32 が ESP-NOW でもう 1 台の ESP32 に送ります。受け取った ESP32 は先頭を `0xA6` にして STM32 に渡します。

ほかのチームの電波を取り違えないように、ESP32 は送ってきた相手の MAC アドレスを確かめます（`robot_receiver.ino` の `REMOTE_MAC` と `ROBOT_MACS`）。

| バイト | STM32 → ESP32 | ESP32 → STM32 |
| --- | --- | --- |
| 1 | `0xA5` | `0xA6` |
| 2 | 機体の番号（`AUTO_ROBOT_ID`） | 同じ |
| 3〜4 | 今いる区画 x, y | 同じ |
| 5〜6 | 次に入る区画 x, y（止まっているときは今いる区画） | 同じ |
| 7 | 状態（`auto_status_t`） | 同じ |
| 8 | 2〜7 バイト目の XOR | 同じ |

- 100ms ごと、または位置が変わったときに送ります。500ms 届かなければ、もう 1 台はいないものとします。
- この向き（STM32 → ESP32）を使うには、STM32 の UART4_TX（PA0、J4 の 1 番）を ESP32 の RX（D7）につなぎます。

### 機体の ESP32 → STM32（UART4、115200bps）

3 バイトで 1 回分です: `0xAA`, ボタン, `0x55`

| ビット | 値 | 名前 | リモコンのボタン | 動作 |
| --- | --- | --- | --- | --- |
| 0 | 0x01 | R | R | アームをホームポジションに戻す（ファン OFF） |
| 1 | 0x02 | B | Back | 吸引ファン ON / OFF |
| 2 | 0x04 | F | F | アームを下ろしてつかむ（ファン ON） |
| 3 | 0x08 | L | L | 投げる |
| 4 | 0x10 | 西 | Y | 押している間、左に回る |
| 5 | 0x20 | 東 | A | 押している間、右に回る |
| 6 | 0x40 | 北 | X | 押している間、前に進む |
| 7 | 0x80 | 南 | B | 押している間、後ろに進む |

- 1 回に押されているボタンは 1 つだけ、という前提です（2 つ同時は無視）。
- リモコンのボタンとビットの対応は、受信用 ESP32 のプログラム（`robot_receiver.ino` の `to_stm32_buttons`）で決めています。
  - 元の受信用プログラムが見つからなかったので、作り直しました。
  - X / B / Y / A をゲーム機と同じように上 / 下 / 左 / 右と考えて、前進 / 後退 / 左旋回 / 右旋回にしています（要確認）。
- 受信用 ESP32 は、リモコンから届いていてもいなくても、50ms ごとに STM32 に送り続けます。リモコンから 200ms 届かなければ、「ボタンなし」を送ります。
- STM32 は、500ms 何も届かなければ止まります（`LINK_TIMEOUT_MS`）。

### STM32 → サーボ RS204MD（USART1）

双葉のショートパケット（`0xFA 0xAF ID Flags Address Length Count Data... Sum`）です。

| 動作 | アドレス |
| --- | --- |
| 角度と時間を指定して動かす | 0x1E |
| トルク ON / OFF | 0x24 |

## 5. プログラムの構成（`software/firmware/MySWEEP1`）

前のリモコン用プログラムは引き継がず、一から書き直しました。前のプログラムから使ったのは、ピンの割り当て、サーボの通信形式、アームの角度といった「ハードの事実」だけです。

```
app.c            いちばん上。リモコン操作・LED・ログ。config.h の ROBOT_MODE で自律走行に切り替える
 ├ app_auto.c    自律走行。ゲート待ち → ボールの隣へ → つかむ → 投げる場所へ → 投げる
 │  └ maze.c     迷路の地図、行き先までの道順（足立法）、投げる場所の選び方。ハードに触らない
 ├ app_arm.c     アームとファンの動作（つかむ・持ち上げる・ホーム・投げる）。待っている間もほかの処理は止まらない
 └ ctl_motion.c  走行。台形加速で「まっすぐ」「その場で回る」「一定の速さで動く」。位置 (x, y, 角度) も計算
    └ ctl_wall.c    横の壁を見た補正（PD 制御）と、壁があるかの判定

drv_stepper.c    ステッピングモーター。速さ → パルス。出したパルスを数える
drv_ir.c         赤外線の壁センサ 4 個と電池電圧
drv_servo.c      サーボ RS204MD との通信（USART1）
drv_fan.c        吸引ファン（TIM4 の PWM）
drv_link.c       受信用 ESP32 からのボタン（UART4）
drv_led.c        基板の LED
drv_time.c       時間（ms と us）
config.h         調整する値はすべてここ
```

`ctl_` は計算をする部分、`drv_` はハードを直接動かす部分です。`main.c` などの CubeMX が作るファイルは、`USER CODE` の中で上の関数を呼ぶだけにしています。

### 動き方

- **1ms ごと（TIM6 の割り込み）**：壁センサを1回測る（`ir_tick`）。そのあと、速さと位置を更新してモーターに渡す（`motion_tick`）。
- **main ループ**：リモコンのボタンを読む → 走行とアームに指令を出す。LED を更新し、ログを出す。
- **モーター**：次の周期の速さは「予約」で書くので、パルスの途中で切り替わりません。回る向きを変えるときは、パルスを1回休んでから方向ピンを切り替えます。
- **壁センサ**：LED1 を点けて測る回と、LED2 を点けて測る回を、1ms ごとに交互に行います。LED は測り終わったらすぐ消します。値は 2ms ごとに更新されます。

### 自律走行で使う関数

```c
motion_straight(CELL_MM, 500, 0, 2000, 1);  // 1 区画（180mm）進んで止まる。横の壁で補正
motion_wait();                               // 終わるまで待つ
motion_turn(90, 360, 2000);                  // その場で左に 90 度
motion_wait();
if (wall_front()) { ... }                    // 前に壁があるか（wall_left / wall_right も）
pose_t p = motion_pose();                    // 今の位置 x, y [mm] と向き [deg]
```

### ログ

USART2（J3 の 2 番 ST-TX、115200bps）に、0.1 秒ごとに次の形で出します。壁センサのしきい値を決めるときに使います。

```
ms,batt_mv,ir_fr,ir_r,ir_l,ir_fl,x_mm,y_mm,theta_x10,v,w,btn
```

### LED

| LED | 意味 |
| --- | --- |
| LED_1 | 動いている間は 1 秒ごとに点滅。電池が少ないと速く点滅 |
| LED_2 | リモコンの信号が届いている間は点灯 |
| LED_T1 | モーターを励磁している間は点灯 |

### ビルドとテスト

- STM32CubeIDE で開いてビルドする
- または `software/firmware/MySWEEP1` で `make` を実行する（`arm-none-eabi-gcc` が必要）
- 走行の計算と壁を見た補正は、`make -C test` で PC 上でテストできる

## 6. 前のプログラムから変わったこと

| 内容 | 前 | 今 |
| --- | --- | --- |
| 制御の周期 | 1ms のつもりが、実際は約 0.73ms（TIM6 が初期値のままだった） | 1ms |
| 速度の計算 | タイマーを 10MHz として計算していて、実際は指定の 1.125 倍速かった | 11.25MHz で計算。**リモコンで走ると前より約 1 割遅くなる**。前と同じ速さにしたいときは `REMOTE_SPEED` を 337 くらいにする |
| 進んだ距離 | 速度を時間で積分していた | 出したパルスを数える。位置 (x, y, 角度) も分かる |
| モーターの速度の切り替え | パルスごとの割り込みで計算していた | 1ms ごとに次の周期を予約する。回る向きを変えるときはパルスを 1 回休む |
| 壁センサの LED | 割り込みの中で数を数えて待っていた | 待ち時間はマイコンのクロックで測る。LED が点いている時間を短くした |
| アームの動作 | 動き終わるまで、ほかの処理が止まっていた | 待っている間も、走行やリモコンの処理が止まらない |
| ボタンを離したとき | すぐに止まっていた | 減速してから止まる |
| リモコンの信号が途切れたとき | 最後のボタンの動きを続けていた | 0.5 秒で止まる |
| 左右の呼び方 | プログラムとピン名で逆だった | ピン名（`.ioc`）どおりにした（下の「確かめること」を参照） |
| `.ioc` の TIM8 | プリスケーラが `tim.c` と違っていた（8 と 16） | 16 にそろえた。CubeMX でコードを作り直しても、片側だけ 2 倍速にならない |
| 調整する値 | あちこちのファイルに散らばっていた | `config.h` にまとめた |

## 7. 実機で確かめること

- [ ] **左右の向き**：前のプログラムは、PC8 のモーターと SENSOR_2 を「左」と呼んでいました。このプログラムでは、ピン名どおり「右」と呼んでいます。ただし、ピンの組み合わせ（どのパルスとどの方向ピンを組にするか）は、前と同じにしてあります。
  - 前進したとき、両方の車輪が前に回るか
  - Y（左）のボタンで左に回るか
  - 前進中に横の壁に近づいたとき、壁から離れる向きに直るか
  - 違っていたら `config.h` の `STEPPER_SWAP_WHEELS`・`STEPPER_*_DIR_FORWARD_HIGH`・`IR_*` を直す
- [ ] ログ（USART2）が出るか。壁センサの値を見て `IR_WALL_SIDE`・`IR_WALL_FRONT`・`IR_CENTER_*` を決める
- [ ] アーム（F・R・L）と吸引ファン（Back）が前と同じように動くか
- [ ] タイヤの直径と、左右のタイヤの間隔。1区画（180mm）進ませて、実際に進んだ距離を測る
- [ ] SLA7073 の分割の設定（今は 1パルスで 0.9度 回るとして計算している）
- [ ] 電池電圧の分圧比（ログの batt_mv と、テスターで測った電圧を比べる）
- [ ] 受信用 ESP32（`robot_receiver.ino`）のボードの種類と UART のピン、リモコンのボタンと動作の対応
