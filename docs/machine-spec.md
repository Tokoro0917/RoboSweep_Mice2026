## 1. 全体の構成

```
 [リモコン]                         [機体]
 XIAO ESP32C3                       ESP32（受信用）
 ボタン 8 個 + 液晶  --ESP-NOW-->    │ UART4 (115200bps)
                                    ▼
                                   STM32F446（DOM-SWEEP 基板）
                                    ├─ ステッピングモーター × 2（SLA7073 × 2）
                                    ├─ 赤外線の壁センサ × 4
                                    ├─ アーム用サーボ RS204MD × 2（USART1）

 （予定）XIAO ESP32S3 Sense のカメラでボールを探し、UART で STM32 に送る
```

### マイコン

- STM32F446RETx
- クロックは内蔵の HSI（16MHz）と PLL で 180MHz
  - 基板には 10MHz のセラミック発振子（Y1）が載っているが、今は使っていない
- 書き込みとデバッグは J3（SWD）

| PB14 | MOTOR_CW/CCW_R | モーターの回転方向 |

### タイマー

| タイマー | 用途 | 設定 |
| --- | --- | --- |
| TIM3 | 片方のモーターのパルス | 90MHz / 8 = 11.25MHz。ARR でパルスの周期を変える |
| TIM8 | もう片方のモーターのパルス | 180MHz / 16 = 11.25MHz |
| TIM4 | 吸引ファンの PWM | 周期 100。比較値 2 で ON、100 で OFF |
| TIM6 | 制御の割り込み | **1kHz**（1ms ごと） |

## 4. 通信

### リモコン → 機体の ESP32（ESP-NOW）

リモコンは 50ms ごとに、8 個のボタンの状態（`bool` × 8 の構造体）を送ります。

### 機体の ESP32 → STM32（UART4、115200bps）

3 バイトで 1 回分です: `0xAA`, ボタン, `0x55`

| ビット | 値 | 名前 | 動作 |
| --- | --- | --- | --- |
| 0 | 0x01 | R | アームをホームポジションに戻す（ファン OFF） |
| 1 | 0x02 | B | 吸引ファン ON / OFF |
| 2 | 0x04 | F | アームを下ろしてつかむ（ファン ON） |
| 3 | 0x08 | L | 投げる |
| 4 | 0x10 | 西 | 押している間、左に回る |
| 5 | 0x20 | 東 | 押している間、右に回る |
| 6 | 0x40 | 北 | 押している間、前に進む |
| 7 | 0x80 | 南 | 押している間、後ろに進む |

- 1 回に押されているボタンは 1 つだけ、という前提です（2 つ同時は無視）。
- リモコンのボタン名（A / B / X / Y / L / R / F / Back）と、上のビットの対応は、受信用 ESP32 のプログラムで決まっています。**そのプログラムはまだリポジトリにありません。**
- 信号が 500ms 届かないと、STM32 はボタンが離されたとみなして止まります（`REMOTE_TIMEOUT_MS`）。そのため、受信用 ESP32 はボタンを押している間、データを送り続ける必要があります（要確認）。

### STM32 → サーボ RS204MD（USART1）

双葉のショートパケット（`0xFA 0xAF ID Flags Address Length Count Data... Sum`）です。

| 動作 | アドレス |
| --- | --- |
| 角度と時間を指定して動かす | 0x1E |
| トルク ON / OFF | 0x24 |

## 5. プログラムの構成（`software/firmware/MySWEEP1`）

```
app.c          いちばん上。リモコン操作モード（自律モードはここに足す）
 ├ motion.c    台形加速で「まっすぐ進む」「その場で回る」「一定の速さで動く」
 │  ├ motor.c        ステッピングモーターのパルス。出したパルス数で距離を数える
 │  └ wall_sensor.c  壁センサと電池電圧。横の壁を見た補正にも使う
 ├ arm.c       アームの動き（つかむ・ホーム・投げる）と吸引ファン
 │  └ servo.c        RS204MD との通信
 └ remote_link.c  受信用 ESP32 から届くボタンを受け取る
config.h       寸法・速度・しきい値・アームの角度など、調整する値をすべてここに
```

- 1ms ごとの割り込み（TIM6）で、壁センサの測定と `motion_tick()` を呼んでいます。
- `main.c` などの CubeMX が作るファイルは、`USER CODE` の中で上の関数を呼ぶだけにしています。

### ビルド

- STM32CubeIDE で開いてビルドする
- または、STM32CubeIDE がなくても `software/firmware/MySWEEP1` で `make` を実行するとビルドできる（`arm-none-eabi-gcc` が必要）
- 走行の計算は `make -C test` で、PC 上でテストできる

## 6. 前のプログラムから変わったこと

`software/firmware/MySWEEP1` は、前のリモコン用プログラムを作り直したものです。ハードウェアを動かす部分は前と同じやり方のままにしてあります。

| 内容 | 前 | 今 |
| --- | --- | --- |
| 制御の周期 | 1ms のつもりが、実際は約 0.73ms（TIM6 の設定が初期値のままだった） | 1ms |
| 速度の計算 | タイマーのクロックを 10MHz として計算していて、実際は指定の 1.125 倍速かった | 11.25MHz で計算。**リモコンで走ると前より約 1 割遅くなる**。前と同じ速さにしたいときは `REMOTE_STRAIGHT_SPEED` を 337 くらいにする |
| 進んだ距離 | 速度を時間で積分していた | モーターに出したパルスを数えている |
| ボタンを離したとき | すぐに止まっていた | 減速してから止まる |
| リモコンの信号が途切れたとき | 最後のボタンの動きを続けていた | 500ms で止まる |
| 速度 0 を指定したとき | 遅いパルス（約 71mm/s 相当）が出続けていた。励磁を切っていたので、止まっているときは動かなかった | パルスを止める |
| `.ioc` の TIM8 | プリスケーラが `tim.c` と違っていた（8 と 16） | 16 にそろえた。CubeMX でコードを作り直しても片側だけ 2 倍速にならない |
| 調整する値 | 各ファイルに散らばっていた | `config.h` にまとめた |

## 7. 実機で確かめること

- [ ] **左右の注意**：前のプログラムで「左」と呼んでいた車輪は PC8 と PB15 で動かしていました。しかし `.ioc` のピン名では PC8 = `MOTOR_CLOCK_R`（右）、PB15 = `MOTOR_CW/CCW_L`（左）です。今のプログラムは前と同じ組み合わせにしてあります。
  - 前進したときに両輪が前に回るか確かめる
  - 「左」に回るボタンで本当に左に回るか確かめる
  - 横の壁に寄ったときに、壁から離れる向きに補正されるか確かめる
- [ ] 作り直したプログラムで、リモコンのすべてのボタンが前と同じに動くか

- [ ] SLA7073 の分割の設定（今は 0.9 度 / パルスとして計算）
- [ ] 電池電圧の分圧比
